# Fork decision log

The repo-root `DECISIONS.md` is upstream's log and is append-only upstream, so
writing fork-specific entries into it would put our lines into a file upstream
rewrites on every release: guaranteed merge surface, in the one file whose whole
value is that it reads as a single project's history. Fork decisions go here
instead. Same format: `[YYYY-MM-DD] <decision>: <why>`.

[2026-08-22] The whole fork layer lives in `fork/` and modifies zero upstream files: every upstream file we touch is a file that must be merged by hand forever, so `git diff upstream/main...HEAD` staying inside one new directory is the property worth optimising for. This is why there is no pointer to fork/README.md in the root README.md and no npm scripts in package.json; the entry point is `npx tsx fork/cli.ts`.
[2026-08-22] Fork decisions live in `fork/DECISIONS.md`, not in the root `DECISIONS.md`: see the paragraph above. Appending to upstream's log would also make the drift guard flag the file, which would be correct and would then have to be suppressed.
[2026-08-22] No npm scripts were added for the fork commands, even though it costs discoverability: `package.json` is upstream-owned and rebased constantly, and the layer is already reachable from `npm test` where it matters (the committed-manifest test), so the script entries would buy convenience at the cost of the zero-modification property.
[2026-08-22] The scheduled sync is a cron job on the box, not a GitHub Actions workflow: GitHub does not run `on: schedule` in forked repositories at all, so a committed workflow would never fire, and `.github/workflows/` is upstream-owned. Prior attempts at this task shipped a workflow YAML that could not have run.
[2026-08-22] The guard is bidirectional: it flags undeclared files AND declared adaptations that stopped differing from upstream. A one-directional check goes green in exactly the case the order cares about, because a reverted file disappears from the diff versus upstream.
[2026-08-22] Adaptation checks live in a declarative manifest (`fork/adaptations.json`) rather than in code: the parser can then enforce invariants across all of them at once, in particular that a tracked adaptation must carry at least one `local-*` check, which is the mechanical form of "our fixes must never disappear silently".
[2026-08-22] The gate preflight is per gate, not all-or-nothing, and every gate always emits a result line: an earlier design skipped three gates when one runner was missing and named only one of them in the report, which is the false all-clear the layer exists to prevent.
[2026-08-22] Upstream's gates run in a throwaway detached worktree at upstream's tip (`--upstream-gates`), not in our checkout: running our own frozen tree and calling the result "upstream is green" would be false, and the order explicitly asks for both suites.
[2026-08-22] `git worktree add --detach` and `git worktree remove --force` are on the git allowlist; everything that could move HEAD, stage work or touch a remote branch is refused and a test walks a full run to prove it. Running upstream's suite is impossible without a worktree, and neither call touches HEAD, the index or any branch.
[2026-08-22] Exit codes rank adaptation (2) above gate (3) above plumbing (4), with 1 reserved for the launcher, but the report always prints one line per category plus a "deliberately skipped" section: the ranking must not be able to hide a second problem.
[2026-08-22] A deliberate skip (`--skip-gates`, no `--upstream-gates`) is a note, not a plumbing alarm; missing dev tooling is a plumbing alarm. A documented choice going red every Monday is alarm fatigue, and alarm fatigue is how a real alarm gets ignored.
[2026-08-22] Alerting updates an existing open alarm issue instead of filing a new one each week, found via a stable `fork-sync-alarm` title marker. A weekly duplicate trains everyone to ignore the alarm.
[2026-08-22] Staleness is itself an alarm (`status`, `maxSyncAgeDays`), and the crontab pings an external dead-man's switch on success: a scheduled job that quietly died looks exactly like one with nothing to report, and nothing running on the box can report that the box is off.
[2026-08-22] `docker-compose.override.yml` stays untracked on each host with a committed, secret-free template under `fork/templates/`: it is per host and it is what people reach for during an incident, which is precisely the change that must not become a fork commit. Upstream's own docs/DOCKER.md already documents the override as the sanctioned mechanism.
[2026-08-22] The 508-commit gap was measured on the old working clone at ed9bdc4, not on the fork, which has zero commits of its own. Catching up is therefore a fast-forward with nothing to conflict, and the documented risk moves to the 370 migrations dated 2026-05-11 or later.
